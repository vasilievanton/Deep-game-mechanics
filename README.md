# Deep — лендинг «Интерактивные платформы для HR и маркетинга»

Статический сайт на Astro 7 и React 19 (интерактивные «острова»), TypeScript в строгом режиме. Две страницы: главная `/` и список кейсов `/cases`. Светлая тема по мотивам стиля Slush ([styles.refero.design](https://styles.refero.design/style/8b6b547f-a357-4f1b-9842-4579c62dd42b)): чёрные контуры, плоские цветные плашки без теней, узкий жирный гротеск в заголовках.

## Порядок блоков

Главная собирается в `src/pages/index.astro`, порядок блоков меняется там: первый экран → «Механики и возможности» → «Кейсы» → «Для кого мы собираем проекты» → «Как мы работаем» → конструктор → аналитика → FAQ → финальный призыв → подвал. Пункты меню и якоря лежат в `navigation` (`src/data/landing.ts`); держите их в том же порядке, что и блоки. Подсветка текущего раздела в шапке следит за секциями в порядке страницы, так что блоки можно переставлять в `index.astro`, не трогая код шапки. Продукт везде называется «интерактивные платформы»: не «геймификация» и не «игровые механики»; слово «игры» осталось только там, где речь о самих играх внутри платформы (квиз, колесо фортуны).

## Запуск

Нужен Node.js 22.12 или новее.

```sh
npm ci
npm run dev        # http://localhost:4321
npm run build      # проверка типов (astro check) и статическая сборка в dist/
npm run preview    # посмотреть собранный dist/
npm run format:check
```

`dist/` — готовый сайт, его можно выложить на любой статический хостинг. Если домен известен, укажите `site` в `astro.config.mjs`.

## Форма «Обсудить проект»

Все кнопки «Обсудить проект» открывают одно окно с формой (`ContactDialog`). Поля: имя, почта или телефон, сообщение. Под кнопкой стоит уведомление, что отправка заявки означает согласие на обработку персональных данных, со ссылкой на https://deep-agency.ru/policy/ (отдельного чекбокса нет; поле `consent` в заявке фиксирует это согласие). Если форму открыли из конструктора, квиза или кейса, сверху появляется плашка с выбранным контекстом; её можно убрать.

Куда отправлять заявки, задаётся при сборке:

```sh
PUBLIC_FORM_ENDPOINT=https://example.com/lead npm run build
```

Пока адрес пустой, форма работает в **демо-режиме**: проверяет поля, показывает «Спасибо» с пометкой «Тестовая версия» и никуда ничего не отправляет. Пример значения — в `.env.example`.

На адрес уходит `POST` с `Content-Type: application/json`:

```json
{
  "name": "Анна",
  "contact": "+79001234567",
  "contactKind": "phone",
  "message": "Нужен онбординг для 500 человек",
  "project": {
    "label": "Из конструктора: Онбординг · 500 – 2 000 сотрудников",
    "source": "configurator",
    "details": { "Задача": "Онбординг" }
  },
  "page": "/#configurator",
  "sentAt": "2026-10-27T10:00:00.000Z",
  "consent": { "accepted": true, "policyUrl": "https://deep-agency.ru/policy/" }
}
```

`project` равен `null`, если форму открыли без контекста. `source` — откуда пришла заявка: `configurator`, `mechanics-quiz`, `audience-custom`, `audience-telegram`, `page` и т. п. Ответ с кодом 2xx считается успехом, всё остальное, таймаут (12 с) и обрыв связи показывают понятную ошибку, введённое остаётся в полях.

Сайт статический, поэтому адрес виден в коде страницы: используйте webhook/прокси, который принимает заявки без секретов в запросе. Если приёмник на другом домене, он должен отвечать на CORS-запрос (`OPTIONS`) заголовками `Access-Control-Allow-Origin` и `Access-Control-Allow-Headers: Content-Type`. Скрытое поле-ловушка `website` отсекает простых ботов: заявка с заполненным полем не отправляется, а человеку показывается обычный успех.

## Устройство

- **Кейсы.** Шесть проектов в `cases` (`landing.ts`), у каждого поле `theme` с темой бренда. Кейс — короткая история: задача → что собрали (`built`, 3–4 пункта) → итог (`outcome`) плюс проверяемые факты (`facts`: аудитория, срок, формат). Правило наполнения: цифра (`value`) в итоге допустима только подтверждённая, иначе пишем словами, что получилось; выдуманных результатов быть не должно. Сейчас подтверждённые цифры есть только у «МТС · 30 лет» (24 000 участников, 3×, 92 % — из текста команды; аудитория, срок платформы и финал — с публичной страницы проекта «Больше чем цифра» на deep-agency.ru, источники указаны комментарием у кейса). У остальных пяти кейсов цифр нет, итог описан словами: когда команда пришлёт данные, их достаточно дописать в `outcome` и `facts`. Ссылка `/#case-<id>` открывает нужный кейс на главной. Переключатель «Проект» показывается, только если в задаче больше одного проекта. Логотипов клиентов на сайте нет: только цвет, шрифт и форма.
- **Дизайн.** Светлая плоская тема: чёрный (`#000`) — текст, контуры 1px и заливка главной кнопки; белый — карточки; фон блоков — полосы на всю ширину (небесная `#dceeff`, бетонная `#ccc`, дымчатая `#e9e9e9`, белая, мятная, фиолетовая у финального призыва), их рисует `::before` секции по токенам `--band` и `--mark`. Цвета-наклейки (синий `#4da2ff`, мятный `#55db9c`, лавандовый `#e9ccff`, оранжевый `#fb4903`, жёлтый `#ffd731`, фиолетовый `#5c4ade`) используются только как заливки и плашки, никогда как цвет текста на светлом; на фиолетовом текст белый. Теней, градиентов и размытия нет (исключение — панели кейсов в брендовых цветах клиентов). Кнопки — пилюли, карточки — скругление 20px, панели — 32px. Кольцо фокуса — фиолетовое 3px. Имена акцентов задач в `accent.css` — исторические (`blue`, `violet`, `cyan`, `coral`, `amber`, `green`): сейчас они раскрашены в палитру Slush, например `green` — это фиолетовый с белым текстом.
- **Шапка.** Липкая: в начале страницы она того же небесного цвета, что и первый экран, при прокрутке белеет и получает чёрную линию снизу; под ней растёт фиолетовая полоска прогресса чтения, а в меню чёрной пилюлей подсвечивается текущий раздел. Над шапкой — чёрная бегущая строка (`Marquee.astro`): названия механик из каталога и фраза «Запуск на готовых модулях — от 1 недели» (с той же оговоркой, что в конструкторе и FAQ). При `prefers-reduced-motion` лента не движется и перестраивается в строки.
- **Анимации.** Появление блоков, счётчики и графики включает класс `html.motion-ok`; без JavaScript и при `prefers-reduced-motion: reduce` всё видно сразу и ничего не движется. Состояние хранится в `data-in`, а не в классах (React перезаписывает `className`). Не ставьте `data-reveal` на элементы, которые React добавляет позже: наблюдатель видит только то, что было на странице при загрузке. `data-stagger` задаёт только задержку появления в ряду карточек (`Motion.tsx`).
- **Слайдер.** Пять карточек, стрелки и точки: активная точка вытягивается в полоску, в которую «наливается» время до следующего слайда. Отдельной кнопки паузы нет: автопрокрутка стоит, пока над слайдером мышь, в нём фокус с клавиатуры, идёт перетаскивание или он вне экрана, а при `prefers-reduced-motion` её нет совсем. Листается свайпом и клавиатурой. Подробности и «грабли» с pointer-событиями — в комментариях `HeroCarousel.tsx`.
- **Демо мерч-шопа.** В панели механики «Мерч-шоп» есть карточка «Попробуйте витрину»: по клику открывается окно с условным магазином (`MerchShopDemo`). Баланс стартует с 1 240 баллов (как в карточке слайдера), четыре товара. Выбрали товар → «Обменять» → баллы списываются, остаток уменьшается, заказ попадает в список (видны два последних). У худи лимит «1 на человека»; если баллов не хватает или лимит исчерпан, карточка товара гаснет и пишет почему. «Начать заново» и закрытие окна сбрасывают демо. Всё состояние локальное, ничего никуда не отправляется. Товары, цены, остатки и лимиты правятся в `src/data/shop-demo.ts`, компонент лежит в `src/components/sections/MerchShopDemo.tsx`.
- **Иконки.** В теме Slush иконки в «Для кого» и в карточках механик всегда чёткие (`имя-sharp.webp`): плоские наклейки с контуром читаются лучше, чем размытые. Эффект «мягкая в покое, чёткая при наведении» из прежней версии убран; мягкие `имя.webp` остались в репозитории, но не используются (если эффект понадобится снова, это один селектор и подмена файла). Чёткие иконки механик восстановлены из мягких, исходников без размытия не было: если появятся оригиналы, их достаточно положить в `public/images/mechanics/` под теми же именами.
- **Шрифты.** Заголовки, цифры и плашки — Sofia Sans Extra Condensed (в Slush это Lateral), остальной текст — Inter (в Slush это Aeonik): оба открытые аналоги под лицензией SIL OFL с кириллицей. В панелях кейсов — открытые аналоги шрифтов брендов клиентов (Montserrat, Rubik). Файлы woff2 и лицензии лежат в `public/fonts/`, четыре основных файла предзагружаются в `BaseLayout.astro`. Cascadia Mono из прежней версии удалён. Если у Deep есть лицензия на настоящие Lateral и Aeonik, достаточно заменить файлы и имена в `fonts.css` и `--font-display`/`--font-ui` в `theme-deep.css`.

## Что проверялось

Автотесты на Playwright (в репозиторий не входят) гоняли главную и `/cases` на ширинах от 320 до 1920 px: нет горизонтальной прокрутки, консоль и сеть чистые, форма (в демо-режиме и с реальным адресом, включая ошибки сервера и обрыв), квиз, конструктор (9 задач × 4 масштаба × наборы модулей), чипы первого экрана, слайдер, демо мерч-шопа (покупка, нехватка баллов, лимит, сброс, клавиатура, телефон), ссылки на кейсы, подвал, контраст по реальным пикселям (обычный текст не ниже 4,5:1, крупный не ниже 3:1; шапка — отдельно в прокрученном виде), кольца фокуса, обход Tab. Заголовки и кнопки набраны капсом через `text-transform`, поэтому в автотестах текст нужно сравнивать через `textContent` в нижнем регистре, а не через `innerText`.

- `src/components/ui/ThreeDCarousel.tsx` и часть констант в `src/lib/figma-assets.ts` остались от прежних версий и не используются. Не используются и несколько картинок: мягкие иконки `*.webp` (без `-sharp`), `public/images/mechanics-decoration.png`, `deep-spiral.svg`, `coverflow/avatar-*.webp` и часть старых `svg/png` в `public/images/mechanics/`.
- `prettier --check` ругается на файлы, которые были неформатированы до правок (`ThreeDCarousel.tsx`, `cases.astro`, `public/coverflow-reference.html`): не переформатировали, чтобы не раздувать diff. Остальное форматировано.
- Страница `/coverflow-preview` показывает слайдер отдельно, в меню её нет.
- Тексты кейсов, кроме «МТС · 30 лет», без цифр: нужны подтверждённые данные от команды. Для «МТС · 30 лет» стоит подтвердить, что это тот же проект, что на странице «Больше чем цифра».
